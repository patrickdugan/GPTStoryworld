# 9-TRM Encounter Assembly Control Plane

This regimen treats the LLM as a bounded input generator, not as the whole storyworld builder. Each TRM owns one control decision in the encounter assembly flow.

## Roles

- `mcp_context_router`: selects the smallest MCP packet for the encounter.
- `world_state_summarizer`: compresses MeTTa facts, ledger deltas, character beliefs, and threshold pressure.
- `llm_prompt_composer`: turns the state card into a strict bounded authoring request.
- `option_manifold_planner`: asks for or selects option archetypes that expose real variable tradeoffs.
- `reaction_dynamics_mapper`: maps option outcomes into success, mixed, and failure reaction slots.
- `effect_script_synthesizer`: converts narrative intent into effect operators, pValues, p2Values, and constants.
- `gate_secret_route_designer`: designs visibility, performability, clue, and threshold logic.
- `validator_repair_critic`: converts verifier/Monte Carlo failures into typed repair targets.
- `commit_veto_controller`: commits, retries, reroutes, or shrinks context based on measured deltas.

## Principle

The LLM should be asked for local, bounded inputs:

- scene phrasing;
- option candidates;
- reaction text;
- clue lines;
- ambiguity resolution;
- rationale for human-readable intent.

The TRMs should own control:

- context selection;
- role routing;
- tool choice;
- schema translation;
- repair target selection;
- commit/veto;
- metric-aware retry.

## Training Shape

The generated library has three useful views:

- Full trajectories for analysis and paper/demo artifacts.
- `state/tools/action/meta` rows for compact TRM control training.
- Chat/SFT rows for distilling the same policy into a small LLM or Hermes skill prompt.

The first hackathon-scale seed target is 1000 rows and at least 100k estimated tokens. Larger M-token corpora should be generated by adding real failed Hermes traces, validator repairs, MCP budget failures, and before/after score deltas.

## Master Control Planner Layer

The nine role-local TRMs are the first layer. The next layer is a master control planner trained on episodes that chain role decisions across a conveyor run.

The master planner chooses:

- next TRM role;
- context packet size;
- whether to call the LLM;
- LLM call type;
- verifier target;
- commit, retry, shrink-context, or stop.

The episode schema is `hermes-skills/storyworld-conveyor/schemas/trajectory_episode.schema.json`.

The curriculum note is `hermes-skills/storyworld-conveyor/trm_corpus/encounter_assembly_9trm_seed/MASTER_CONTROL_PLANNER.md`.

## 9B Storyworld Factory Mode

9B can be useful if the conveyor treats it as a local component generator. It should be called only for bounded trajectories:

- `ASK_LLM_BOUNDED_DRAFT`
- `ASK_LLM_OPTION_SET`
- `ASK_LLM_REACTION_TEXT`
- `ASK_LLM_CLUE_LINES`
- short rationale for ambiguous theme pressure

Do not use 9B for global storyworld planning, schema translation, acceptance testing, commit/veto, or self-certification.

Use `hermes-skills/storyworld-conveyor/runtime_prompts/9B_Trajectory_Control_Plane.md` as the runtime prompt contract.
